# vrclt v0.19.0

Soniox joins Gemini, Qwen, and OpenAI as a translation engine. Speaker labels
make multi-speaker conversations easier to follow, and the Dashboard and Settings
now group controls by task.

## Changes

- **Soniox speech recognition and translation** for microphone translation and
  inbound subtitles, with optional translated voice. Select `soniox` in Settings
  and enter an API key, or set `SONIOX_API_KEY`.
- **Speaker numbers and colors** in the Dashboard subtitle preview, desktop
  overlay, and VR overlay. Original and translated fragments stay associated with
  their speaker, preserving turn order. Numbers are local to each recognition
  session and can change after reconnecting.
- **Organized controls:** grouped translation, subtitle, language, and audio
  controls; an active-engine shortcut; categorized Settings that show the selected
  engine's options; expandable display and application settings.
- **Runtime improvements:** bounded log history and partial-line buffers, batched
  log updates, correct log-rotation handling, and reconnect waits that wake
  immediately when stopping.
- **Audio and startup fixes:** an unavailable optional monitor output no longer
  blocks primary translated voice output, and failed required audio startup
  cleans up capture, playback, and pipeline workers. CLI `--help` and `-h` now
  exit without starting capture or the runtime.

## Soniox setup and billing

Follow the [Soniox setup guide](../../README.md#3c-soniox-api-key)
([한국어](../../README.ko.md#3c-soniox-설정)) for signup, project API keys,
billing balance, app/language settings, and first-use troubleshooting. This
version connects to Soniox's US endpoints; use a US-project API key.

**Keep speaker context** is on by default
(`soniox.keep_speaker_context: true`). It retains recognition sessions through
short pauses, then disconnects after **60 seconds of silence**. Adjust
`soniox.speaker_context_idle_sec` in Settings (5–600 seconds). The Soniox Dashboard
shows the synchronized checkbox and effective silence timeout. Existing saved
choices are preserved, and speaker diarization remains enabled with either
choice. Longer timeouts avoid reconnections but extend billable time. Soniox bills
the full connected recognition stream, including silence and keepalive periods,
also in text-only mode. See [Soniox keepalive billing](https://soniox.com/docs/stt/rt/connection-keepalive).

With the option off, connections use `audio.mic_idle_disconnect_sec` instead
(15 seconds by default). Reconnecting creates a new speaker context. Turn
boundaries and endpoint sensitivity are more conservative to reduce premature
finalization, but a persistent session does not guarantee stable speaker numbers
for one person. Different IDs returned by Soniox remain separate. Optional translated
voice uses the configured Soniox TTS voice (`Daniel` by default); speaker labels
do not automatically clone each speaker's voice.

## Installation

Download `vrclt-v0.19.0-windows-x64.exe` and its `.sha256` checksum from the release
assets. This is a single Windows executable with a native PySide6 window and
tray menu. VB-Audio Virtual Cable is required for virtual microphone routing;
set the target application's microphone to `CABLE Output`.

Existing settings remain in `%LOCALAPPDATA%\vrclt\config.yaml`. Configure the
selected translation engine's API key in Settings. No configuration file is
bundled alongside the executable.

## Validation limits

Soniox has local mock-WebSocket regression coverage, including speaker metadata
and ordering. Paid live Soniox calls, real speaker-recognition accuracy, and
physical VR headset behavior have not been verified.
